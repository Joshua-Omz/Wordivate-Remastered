# Architectural Standards & Technical Boundaries

## 1. System Topology & Technology Stack

The Wordivate system consists of two primary applications and a relational datastore:
1. **Backend Server (`backend/`):** Written in **Go 1.25+**, using standard library idioms, `chi/v5` router, `sqlc` for type-safe database queries, and WebSocket/SSE streaming.
2. **Mobile Client (`client/`):** Built with **Flutter (Dart >=3.3.0 <4.0.0)** with Material 3 design and offline-safe state management.
3. **Database:** **PostgreSQL 16+** with `pgcrypto` (UUID v4), `pg_trgm` (trigram fuzzy matching), and `citext` extensions.

```

|                 Flutter Client (Mobile / Dart)              |
```

## 2. Backend Architecture Rules (Go)

### 2.1 The Strict 4-Tier Clean Architecture Layering

Every backend feature in `backend/internal/features/<feature>/` must strictly enforce the following 4 tiers:

1. **Tier 1: Data Access Layer (`backend/internal/database/sqlc/`)**
   - Auto-generated type-safe code generated by `sqlc`.
   - Never modified by hand.

2. **Tier 2: Repository Layer (`repository.go`)**
   - Implements data persistence for the feature.
   - **Constraint:** This is the ONLY feature layer permitted to import `database/sql` or `internal/database/sqlc`.
   - Defines and implements a feature-specific repository interface (e.g., `UserRepository`).
   - Maps raw database rows/structs into pure domain models (e.g., converting `sql.NullString` to standard Go types/pointers).

3. **Tier 3: Service Layer (`service.go`)**
   - Contains pure business logic, validation, and domain orchestration.
   - **STRICT PROHIBITION:** The service layer MUST NEVER inject `*database.DB`, `*sql.DB`, or call `sqlc` directly.
   - **Constraint:** Must interact with the database exclusively via injected Repository interfaces.
   - **Constraint:** Must NEVER import HTTP packages (`net/http`, `chi`).

4. **Tier 4: Handler Layer (`handler.go`)**
   - Handles transport serialization (HTTP/SSE/WebSocket).
   - Injects the Service interface.
   - **Constraint:** Contains NO business logic and makes NO database calls. Parses requests, invokes the service, and serializes responses.

- **`backend/cmd/api/main.go`:** Composition root ONLY. Responsible for config loading, connection initialization, dependency injection (wiring repository -> service -> handler), and graceful OS shutdown signals (`SIGINT`, `SIGTERM`). Do NOT place business or routing logic in `main.go`.
- **`backend/internal/middleware/`:** Cross-cutting concerns (CORS, request logging, panic recovery, JWT authentication, and rate limiting).

### 2.2 Provider Abstraction & Isolation (NFR-M1, NFR-S3)
- **Zero Third-Party Client Leaks:** The Flutter client MUST NEVER directly communicate with third-party LLM providers (e.g., Gemini, OpenAI, Claude) or dictionary APIs.
- **Interface Segregation:** Domain services must depend on Go interfaces, not concrete client structs:
  ```go
  type LLMClient interface {
      StreamChat(ctx context.Context, sessionID uuid.UUID, messages []Message, systemPrompt string) (<-chan StreamToken, error)
      AssessCommit(ctx context.Context, input CommitAssessmentInput) (*CommitAssessmentOutput, error)
  }

  type DictionaryClient interface {
      FetchDefinition(ctx context.Context, headword string) (*DefinitionResult, error)
  }
  ```
- This ensures LLM models and dictionary providers can be swapped or mocked in automated tests without altering domain code.

## 3. Database & Persistence Standards (PostgreSQL)

### 3.1 Schema Management & SQLC Workflow
- All database modifications must be authored as versioned SQL migration scripts in `backend/sql/schema/` (e.g., `001_init.sql`, `002_add_vocab_tables.sql`).
- All queries must be defined in `backend/sql/queries/*.sql` and compiled to type-safe Go structs via `sqlc generate`.
- Do not use heavyweight object-relational mappers (ORMs) that obscure query execution plans or bypass indexing.

### 3.2 Multi-Tenant Data Isolation (NFR-S2)
- Wordivate is a multi-user application where learning conversations and vocabulary are private.
- **Mandatory User Scoping:** Every SQL query fetching, modifying, or deleting user assets (`learning_sessions`, `messages`, `vocab_entries`) MUST parameterize `WHERE user_id = $1`. Never rely on client-provided IDs without verifying tenancy against the authenticated JWT context.

## 4. Client Architecture Rules (Flutter)

### 4.1 Feature-First Modular Organization
Code inside `client/lib/` must adhere to a feature-sliced directory structure:
- `client/lib/features/<feature_name>/`
  - `presentation/`: Widgets, screens, and view controllers.
  - `application/` or `providers/`: State management and business logic.
  - `data/`: Repositories and HTTP/WS API client communication.
- No cross-feature cyclic dependencies. Shared widgets or utilities belong in `client/lib/shared/` or `client/lib/core/`.

### 4.2 Latency & Resilience Requirements
- **Capture-to-Chat Visibility (NFR-P1):** The transition from capturing a word on the home screen to opening the interactive chat must render in **< 1.0 s** at p95.
- **Immediate Streaming Feedback (NFR-P2):** The first AI token must be reflected in under 3.0 s, accompanied by immediate typing indicators.
- **Local Draft Buffering:** If the client loses network connectivity during a session, unsent message drafts must be buffered locally and the UI must present an offline banner with explicit retry options.
